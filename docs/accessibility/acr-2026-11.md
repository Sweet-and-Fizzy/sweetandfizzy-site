# sweetandfizzy.com Accessibility Conformance Report

Draft, November 9, 2026. Sweet & Fizzy Digital.

This is a dated snapshot. The working copy is a shared Claude doc; refresh this file from it before sending a final version, and start a new dated file for the next evaluation.

## Report details

The Phase 1 site, a pre-launch build, supports every applicable WCAG 2.2 Level A and AA criterion but one. 1.4.5 Images of Text is partial because some illustrations and diagrams hold text as pictures. Screen reader testing has not been done yet and is the main open item.

| Version | Pre-launch build, commit 95f1b22 on main, live at sweet-and-fizzy.netlify.app, November 9, 2026 |
| Evaluated by | Sweet & Fizzy Digital (self-evaluation, not a third-party audit) |

Conformance terms follow the VPAT. **Supports** means no known defects. **Partially Supports** means some content does not meet the criterion, or it has not been fully verified. **Does Not Support** means most content fails. **Not Applicable** means the site has no content the criterion covers.

## How it was evaluated

Three kinds of checks ran against the production build. The axe, reflow, touch target and no-JavaScript checks run again before every launch through the launch gate, `npm run check:launch`.

1. **Automated rules.** axe-core 4.14, the engine behind Deque's axe tools, checked every page at phone (390 px) and desktop (1280 px) widths against its WCAG 2.0, 2.1 and 2.2 A and AA rules. Lighthouse 13.6 checked every page in mobile and desktop modes.
2. **Scripted checks** for things rules engines miss:
   - reflow at 320 px
   - text spacing overrides
   - keyboard order and visible focus
   - the skip link
   - focus moving into and back out of the image viewer
   - 44 px touch targets
   - one H1 and no skipped heading levels
   - page titles and the language attribute
   - alt attributes on every image
   - content still visible with JavaScript off and with reduced motion
3. **Review of the code and content**: form labels and error messages, link text, alt text wording and color choices.

Not done yet:

- Testing with a screen reader (VoiceOver and NVDA).
- 200% browser zoom checked by eye.
- WAVE. Its free version is a browser extension that needs a person to run it, and its API is paid. It checks much the same rules as axe. It is worth running by hand on a few pages after deploy.
- Testing with users with disabilities.

## WCAG 2.2 Level A

All 22 applicable Level A criteria are supported. Nine don't apply because the site has no audio, video, time limits, keyboard shortcuts, gestures, motion input or multi-step forms.

| 1.2.2 Captions (Prerecorded) | Not Applicable | No video. |
| 1.2.3 Audio Description or Media Alternative (Prerecorded) | Not Applicable | No video. |

| 1.3.3 Sensory Characteristics | Supports | Instructions don't rely on shape, color or position. |

| 1.4.2 Audio Control | Not Applicable | No audio. |
| 2.1.1 Keyboard | Supports | Navigation, the Services menu, the mobile menu, the contact form and the image viewer all work by keyboard. |

## Lighthouse

On the live preview at sweet-and-fizzy.netlify.app, every page scores 100 in Lighthouse 13.6 for performance, accessibility and best practices, on mobile and desktop. The one exception is the MGHPCC case story on mobile, at 96 for best practices because one image is served at too low a resolution. SEO reads 66 on every page only because the preview sends a noindex header to stay out of search. That header comes off at launch. Layout shift is 0.001 or less, and main-thread blocking is 40 ms or less.

## Issues found and open items

Two defects turned up during this evaluation, and both are fixed. Each now has a test in the launch gate.

| Issue | WCAG | Fix |
| --- | --- | --- |
| Case stories scrolled sideways at 320 px | 1.4.10 Reflow | Chapter headings with their ring icon were wider than a 320 px screen. They now scale down below 420 px, and long words can wrap. A 320 px reflow test now runs on every page. |
| AI agents header dots pulsed forever | 2.2.2 Pause, Stop, Hide | They now pulse twice and stop. The no-JavaScript test fails if any animation loops forever. |

Open items, in order:

- [ ] Test the main pages with VoiceOver on macOS and iOS, and with NVDA on Windows.
- [ ] Redraw the text-bearing illustrations as HTML or SVG text, to fully meet 1.4.5.
- [ ] Check 200% browser zoom by eye on each page.
- [ ] Run the WAVE extension on a few pages after deploy.
- [ ] Keep the accessibility statement at /accessibility/ current as these items close.
