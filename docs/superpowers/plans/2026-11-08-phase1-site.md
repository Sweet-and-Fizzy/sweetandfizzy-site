# Sweet & Fizzy Phase 1 Site Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A static Astro site on Netlify carrying the research computing half of the Sweet & Fizzy Digital redesign, live before SC26.

**Architecture:** Each page is an Astro page built from shared layout and section components that port the markup and CSS of the wireframe boards. Copy lives in Markdown/frontmatter content files, separate from layout, so approved copy is swapped in without touching components. A check script scans the built `dist/` for leftover `[PLACEHOLDER]` brackets and broken internal links; it warns on normal builds and fails the launch build.

**Tech Stack:** Astro 5 (static output, no client framework), plain CSS with custom properties, Astro content collections (zod schemas), Netlify (hosting, Forms, deploy previews), Node 24 `node:test` for the check script, Playwright with `@axe-core/playwright` for the page sweep (dev dependencies only).

**Page sweep:** `tests/sweep.spec.ts` visits every built HTML page (served from `dist/` with `astro preview`) at 390×844 and 1280×800 and asserts, per page and width: zero axe violations tagged `wcag2a`, `wcag2aa`, `wcag21aa`, `wcag22aa`; `document.documentElement.scrollWidth <= window.innerWidth`; every visible `a, button, input, select, textarea, summary` has a bounding box of at least 44×44 or is inline text inside a paragraph; and, with JavaScript disabled, no element in `<main>` has computed `opacity: 0`. It discovers pages from `dist/`, so every later task's pages are covered without editing it. `npm run sweep` runs it; `npm run check:launch` runs it too.

**Spec:** "Phase 1 launch" section of the Site Content Plan doc (https://claude.ai/artifact/HBjXLazyBokSTniJvYwpK7), its Draft copy tab, and the Site Wireframes canvas (https://claude.ai/artifact/JZi77phd2VZJZEFj4ZYyj9). Source boards: `ServicesAll.dc.html` (homepage), `ConnectCI.dc.html`, `Publications.dc.html`, `CaseAccessSupport.dc.html`, `CaseStudy.dc.html` (ACCESS AI Assistant), `CaseOOD.dc.html`, `CaseMGHPCC.dc.html`, `CaseStories.dc.html`, plus `project/ds/sweetfizzy/tokens.json`.

## Global Constraints

- Repo: `Sweet-and-Fizzy/sweetandfizzy-site`, private. Local: `~/Sites/sweetandfizzy-site`.
- No Claude attribution in commits or PRs.
- Fonts: DM Sans (opsz, 400/600/700) and Oswald 500, from Google Fonts, as on the boards.
- Brand colors as on the boards: blue `#5abdff`, orange `#ef4326`, yellow `#fcee21`, ink `#111111`, panel `#1c1c1c`. Exact token values come from `tokens.json`; do not invent new ones.
- Port the boards' interaction details as CSS: `.btn` stroke-to-fill hover, `.go-lk` circle arrow, `.door` hero cards, `.op` notched section opener, `.cs` case tiles, scroll-rise (`.rv`) and bar-draw (`.grow`) motion gated on `html.mo` and `prefers-reduced-motion: no-preference`.
- Zero client JS except one small inline module: the IntersectionObserver motion script from the homepage board, and the contact form helper (Task 6).
- Copy rules (content plan voice guide): specific over impressive, plain words, acronyms explained once, every page ends with one next step, no text in images, real alt text.
- Phase 1 pages only: `/`, `/connect-ci/`, `/services/ai-agents/`, `/planning-a-proposal/`, `/publications/`, `/contact/`, `/work/` (case stories landing), `/work/access-support/`, `/work/access-ai-assistant/`, `/work/open-ondemand/`, `/work/mghpcc/`, `/privacy/`. Startups and Websites cards on the homepage stay but link nowhere deeper yet (anchor to their own homepage section or to `/contact/`).
- Accessibility target: WCAG 2.2 AA. Text contrast 4.5:1 (3:1 for 24px+). Blue `#5abdff` and yellow `#fcee21` are never text colors on white; they stay strokes, bars and fills behind ink text. Touch targets at least 44×44px. Every page has `lang="en"`, a skip link to `<main>`, one `<h1>` and headings in order, visible `:focus-visible` outlines, and real `<a>`/`<button>`/`<label>` elements.
- Mobile: every page works from 360px up with no horizontal page scroll; wide tables scroll inside their own box. Body text at least 16px on phones.
- Communities count is 13 everywhere.
- A client quote with no `quote` value is not rendered; no bracketed quote ships.
- HUST paper: shown as "Presented at HUST @ SC26" with no link until a DOI exists.

## Decisions made by Claude (Andrew to check)

- Mobile nav (the boards have none): below 900px the header shows the logo, a Contact us button and a "Menu" button (`aria-expanded`, `aria-controls`) that opens a full-width panel with the nav links stacked at 44px+ rows. Escape and the button close it; focus returns to the button. Without JS the links render as a wrapped row under the logo, so nothing is unreachable.
- Nav for Phase 1: AI agents · Connect.CI · Case stories · Publications · Planning a proposal · Contact us (button). The board's "Curated catalogs" nav item and page are dropped for Phase 1; the homepage Curated catalogs offer links to `/work/open-ondemand/#appverse`.
- AI agents, Planning a proposal and Contact have copy in Draft copy but no board; they are built from the shared section components in the case study/Connect.CI style.
- The Claude Doc stays the copy-editing surface for Andrew and Lissie through launch; Claude syncs approved sections into the content files. After launch the repo is the source of truth.
- Forms use Netlify Forms (no backend). Analytics via the existing GTM container `GTM-TZHC8GN`, pushing `generate_lead` with `lead_source` to `dataLayer`.
- DNS cutover of sweetandfizzy.com from the cPanel WordPress site is a separate step Andrew triggers; until then the site lives at the Netlify subdomain with `noindex`.

## Review Focus

1. Phone width (390px): hero doors, `.op` openers, `.two`/`.three` grids and the membership table must stack or scroll in a box with no horizontal page scroll. The page sweep's scroll-width check covers every page; Task 9 adds real phones.
2. JavaScript off or blocked: every `.rv` element must be visible. Test in Task 1: built HTML contains no inline `opacity:0`, and the hiding rule is scoped under `html.mo`.
3. A case study with a missing image: render the labelled placeholder box, never a broken `<img>`. Test in Task 2: schema makes `image` optional and the component renders `.ph` when absent.
4. Placeholders shipping: any `[` + capital letter bracket text in `dist/` fails `npm run check:launch`. Test in Task 1.
5. Contact form spam and lost leads: Netlify honeypot field present, and `generate_lead` fires only after a successful submit, not on click. Test in Task 6.
